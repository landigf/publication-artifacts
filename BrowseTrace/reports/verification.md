# BrowseTrace evidence verification

The publication component was checked on 6 October 2026 using Python 3.12.7 and locked libCacheSim 0.3.3.post4, Matplotlib 3.9.2 and NumPy 2.2.6. A fresh isolated environment resolved the complete dependency closure with compatible ContourPy 1.3.3; `pip check` passed. The full closure is pinned in `requirements-lock.txt`. `REPRODUCE.sh` passed the explicit manifest, 1,621 unique census IDs, 1,611 unique liveness IDs, schema/privacy/denominator checks, and all 60 cache simulations. Regenerated statistics, TeX macros, five TeX tables and all six PDF/PNG files matched the release bytes. The complete machine-readable run is `reports/reproduction/verification.json` (a generated local output, excluded from archives).

Bounded-capacity fixtures covered all six policies on a repeated scan of ten 60-byte objects in a 100-byte cache. An LRU fixture separately checked eviction, and a zero-size fixture verified the positive-size request denominator. These fixtures address the simulator API misuse observed in a separate historical project; they do not establish production HTTP serving correctness.

The entire key export was bijective across both inputs and retained row order, timestamps, object sizes and agent labels. Legacy session labels were enumerated into opaque labels. All 60 source versus exported request/byte results agreed exactly; see `input-transformation.json` and `opaque-replay-equivalence.json`. The ephemeral HMAC secret and original key mapping were discarded. Reproduction uses the fixed released CSVs.

The main corpus is 400 scripted plus 911 LLM attempts, with 813 nonempty and 98 empty LLM attempts. The separate 300 local LLM observations and ten observations from one human participant are not added to that corpus. Census and liveness projections agree as multisets of model/region/task/request/nonempty attributes. Liveness predicates were recomputed from supplied counts, not from omitted raw URLs.

The complete historical public scripted JSON and summaries agree at 400 sessions, 168,067 requests and 2,236,749,954 object-size bytes. Its positive-size request count, size multiset and timestamp/size multiset match the 82,455-row scripted replay; 85,612 zero-size records are omitted. An initially inspected private copy contained only 80 of the 100 Zurich trace sessions; its missing files explain that initial discrepancy. The source-level audit is `data/provenance/scripted-replay-projection-audit.json`. No raw JSON was copied into this release.

The collection-source audit records 400 scripted attempts at 15 steps, and main LLM attempts at 20 steps (810), eight steps (100) and ten steps (one). All 300 local comparison attempts use 20 steps. Thus the approximately 3.3–4.2x amplification belongs to the local comparison. The main all-attempt ratio is 0.935 and the nonempty LLM ratio is 1.047. No causal significance or task-success result is retained.

Credential negative fixtures cover Authorization, Proxy-Authorization, Cookie, Set-Cookie, API-Key, ApiKey, X-API-Key, X-Goog-API-Key, X-Amz-Security-Token, X-Auth-Token, X-Access-Token and X-Authorization. Shared capture/export filtering and recursive JSON filtering reject them case-insensitively. Real collector constructors were also tested without starting a browser or model; see `collection-privacy-verification.json`. Published replay/provenance data contain no credential fields and all replay keys are opaque. Historical public repository privacy cleanup remains separate from these release checks.

These checks establish released arithmetic, transformation evidence and offline reproducibility. They do not establish historical semantic task success, an exact historical browser/model environment, origin HTTP cache eligibility, live deployment performance or institutional/contractual publication clearance. The original collection projections remain historical evidence with their stated limitations.

Positive-size object identity is not size-stable: 3,136 of 17,144 scripted keys and 5,637 of 17,931 LLM keys have differing positive sizes. In the pinned policies, a hit does not update the stored object size; new admission uses its incoming size. Byte-hit numerators use current request sizes. Capacity therefore bounds this admission-time accounting, not verified physical HTTP representation bytes. `reports/replay-size-audit.json` reproduces the counts, and six-policy fixtures verify this behavior.
